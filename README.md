# nama_DL

<img src="extension/icons/nama_DL.png" alt="nama_DL" width="128">

YouTube・ニコニコ動画の一覧やプレイヤー、X（Twitter）の投稿から、動画・音声・サムネイルを保存するWindows向けブラウザー拡張機能です。

**現在のバージョン：1.13.0** · Windows 10/11 x64 · Brave / Google Chrome

## ダウンロード

[配布用ZIPをダウンロード](https://github.com/kokenamazu-boop/nama_DL/raw/refs/heads/main/downloads/nama_DL-Windows-v1.13.0.zip)

上のリンクから **`nama_DL-Windows-v1.13.0.zip`** を保存し、「すべて展開」したフォルダーの **`START_HERE.html`** を開いてください。

## 主な機能

- 動画一覧のカードから、動画ページを開かずに保存。
- 動画プレイヤーの操作バーからダウンロードメニューを表示。
- X（Twitter）の動画付き投稿では、共有ボタンの隣から保存。タイムライン・検索・プロフィール・投稿ページに対応。
- Xの1投稿に動画が複数ある場合は、その投稿の動画をまとめて保存。
- ニコニコのマイリスト、YouTubeの再生リスト全体を一括保存。
- 複数の保存依頼をキューに追加し、1件ずつ順番に処理。待機一覧・一時停止・削除・再試行に対応。
- 動画は取得できる最高解像度・フレームレートを優先し、H.264/AACのMP4に保存。
- 対応するH.264/AACは再圧縮せず高速保存。その他は高品質設定で変換。
- 音声のみは24bit PCMのWAV、サムネイルのみはPNG。
- サムネイル・メタデータの埋め込み、保存先のフォルダー選択。
- 開始・終了時刻を指定して、指定位置に合わせてMP4／WAVを切り出して保存。
- LUFSを測定し、曲全体に同じゲインをかけて音量を調整。どちらも初期状態はOFF。
- ファイル名は動画タイトル。同名の場合は連番で保存。
- MP4の確認に成功した後、作業用ファイル・元MKVを整理。

動画カードのボタンはその1本、リストのボタンはリスト全体を保存します。ページ内ボタンの配色はYouTubeのダーク／ライトに追従します。

## 初回導入

1. 配布用ZIPを右クリックして「すべて展開」。移動しない場所に置きます。
2. Braveは `brave://extensions`、Chromeは `chrome://extensions` を開きます。
3. デベロッパーモードをONにし、「パッケージ化されていない拡張機能を読み込む」から `extension` フォルダーを選びます。
4. ツールバーのnama_DLを開き、「初回セットアップ・接続確認」→「IDをコピー」。
5. `Setup.cmd` を実行し、IDを貼り付けてEnter。
6. セットアップ完了後、拡張機能とPC側が両方 `1.13.0` であることを確認し、対象サイトを再読み込みします。

Python専用版・yt-dlp・FFmpeg・FFprobe・Denoはセットアップ時に自動取得します。初回はインターネット接続と数百MBの空き容量が必要です。管理者権限や別途Pythonの導入は不要です。

ニコニコのログインが必要な動画やプレミアム画質には、使用するブラウザーでログインし、「このサイトのログイン情報を使う」を有効にしてください。

## X（Twitter）で使う

動画付き投稿の共有ボタンの隣にあるダウンロードアイコンを押し、保存内容を選びます。動画を開いたり、再生を始めたりする必要はありません。1投稿内の複数動画は、動画ごとのファイルとして保存します。画像だけの投稿にはボタンを表示しません。

ログインが必要な投稿は、詳細設定の「このサイトのログイン情報を使う」をONにしてください。X全体の投稿一覧を一括取得する機能ではありません。

## ダウンロードキュー

保存内容を選んで **「キューに追加」** を押します。空いていればすぐ開始し、処理中でも別の動画・リスト・投稿を追加できます。ポップアップとページ内メニューの「ダウンロードキュー」に共通の一覧が表示されます。メニューや元の動画タブを閉じても処理は続きます。ブラウザー本体は開いたままにしてください。

- **設定の保持**：形式・保存先・切り出し・LUFS・ログイン情報の使用設定は追加時の内容で固定します。後から変更しても既存の待機項目には影響しません。Cookie本体をキューへ保存せず、開始時に同じブラウザープロファイルから読み取ります。
- **一時停止／再開**：現在の処理が終わったところで止まります。途中の取得・変換を一時停止する機能ではありません。
- **削除／中止**：待機項目は一覧から削除できます。「処理を中止」は現在の1件を停止し、キューが一時停止中でなければ次へ進みます。
- **失敗／再試行**：通常の取得・変換エラーでは次へ進みます。失敗・中止・接続中断の項目は「再試行」で最後尾へ戻せます。初回セットアップ未実行・PC側の版違いでは残りを一時停止します。
- **ブラウザー終了・接続切れ**：待機一覧を保持し、実行中だった項目を「接続中断」にしてキューを一時停止します。保存済みのファイルを確認し、必要な項目だけ再試行してから再開してください。途中からの再開や、すでに保存したリスト内動画の自動除外は行いません。
- **件数**：実行中を含む待機依頼は最大100件、結果履歴は直近20件。同じURL・設定の待機／実行中依頼は重複追加しません。再生リスト・マイリストや複数動画の投稿は、全体を1件の依頼として扱います。

## 切り出し・音量調整

ページ内メニューと拡張機能のポップアップにある「切り出し・音量調整」を開いて設定します。

- **指定した区間だけ保存**：開始・終了を秒数、分:秒、時:分:秒で指定できます（小数3桁まで）。開始が空欄なら先頭、終了が空欄または動画長を超える場合は末尾まで。開始位置が末尾以降の項目はエラーになります。再生中の対象動画では「現在位置」から入力できます。
- **指定位置での切り出し**：MP4は映像・音声を再圧縮して、映像はフレーム、音声はサンプルの精度で切り出します。指定区間の前後3秒を含む部分取得を優先し、元動画の時刻と映像・音声の範囲を検証してから切り出します。取得段階では再圧縮せず、最後の切り出し・H.264保存・必要なLUFS調整にまとめます。指定位置を正確に合わせるため、H.264素材でも切り出し時には再圧縮します。部分取得に失敗した場合、時刻や範囲を確認できない場合、変換に失敗した場合は全体取得で再試行します。サイト・配信形式によって取得量や速度改善の効果は異なります。WAVの切り出しは非圧縮で保存します。
- **LUFSで音量をそろえる**：初期目標は−15 LUFS、−40〜−5 LUFSで変更可能。保存する区間のIntegrated LUFSを測定し、全区間・全チャンネルに同じゲインを適用します。コンプレッサー・リミッターは使用しません。True Peakの上限−1 dBTPを優先するため、目標に届かない場合は完了欄に実測値と理由を表示します。保存後も測定し、AAC変換でピークが増えた場合は元データから固定ゲインを下げて再保存します。

両方OFFなら従来の保存処理を使用し、LUFS解析は実行しません。サムネイルのみの保存には適用しません。切り出し範囲は対象URLごとに引き継ぎ、別URLではOFFになります。LUFSのON/OFFと目標値は記憶します。

リストや1投稿内の複数動画では各動画に同じ区間・目標を適用し、動画ごとに音量を測定します。無音や非常に短い音声等でLUFSを測定できない場合は、音量を変更せず結果に表示します。失敗・中止した項目の元データは作業用フォルダーに残します。部分取得したリスト・複数動画は、全件の確認後に保存先へ移動し、全体取得への再試行で完成ファイルが重複しないようにします。完了欄に部分取得／全体取得の方式を表示します。

## 保存形式・データの扱い

変換が必要な動画は再圧縮が入ります。解像度は縮小せず、HDRはSDR、可変フレームレートは固定へ変換します。実際に取得できる画質は、サイト・元動画・ログイン状態に依存します。

ログイン情報の使用をONにしたサイトのCookieをPC側のyt-dlpへ渡します。Cookieを設定・ログへ保存せず、一時Cookieファイルは通常の完了・中止で削除します。独自の外部中継サーバーは使用しません。

## 構成と依存ソフト

- `extension/`：Manifest V3拡張機能
- `host/`：PythonのNative Messaging連携、Windowsフォルダー選択
- `.cmd` / `.ps1`：セットアップ・更新・確認等の補助ツール

依存ソフトは配布ZIPに同梱せず、セットアップで各配布元から取得します。

- [Python](https://www.python.org/)
- [yt-dlp](https://github.com/yt-dlp/yt-dlp)
- [FFmpeg](https://ffmpeg.org/) / [Windowsビルド](https://www.gyan.dev/ffmpeg/builds/)
- [Deno](https://github.com/denoland/deno)

ページ内の新しい配置は模擬ページで検証しています。サイトの表示変更により、ボタンの位置や検出が変わる場合があります。
